## 4. КРИТИЧНЫЕ ЛИМИТЫ (обновлено 12.10.2026)

| Параметр | Значение | Почему |
|---|---|---|
| `.clinerules` текущий | **8166 байт (v7.2)** | Сжат 18.8 → 8.2 КБ |
| **`.clinerules` целевой** | **≤ 8 КБ** | ✅ ДОСТИГНУТО (влезает в num_ctx=16384) |
| `.clinerules` жёсткий минимум | 4 КБ | Для тяжёлых моделей при `num_ctx=16384` |
| `num_ctx` минимум | **16384** | 8192 НЕ ВМЕЩАЕТ `.clinerules` |
| `num_ctx` оптимум для gemma4/gpt-oss | **32768** | Влезают в VRAM полностью |
| `num_ctx` для qwen/laguna/nemotron | **16384** | Не влезают в 16 ГБ |
| `num_predict` (`think=false`) | 1024–2048 | Достаточно |
| `num_predict` (`think=low`) | **16384** | 8192 обрезает qwen3.6-35b |
| `timeout` | **600 с** | `low` может идти долго |

## 5. ТОКЕНЫ vs СИМВОЛЫ
- Английский: 1 токен ≈ 4 символа.
- Русский: 1 токен ≈ **2–2.5 символа**.
- `.clinerules` v6.24 ≈ 4700 токенов (подтверждено: `промпт=4685` для gemma4).

## 6. МЕТОДОЛОГИЯ (для v4/v5/v6)
**Тест проверяет ТОЛЬКО `.clinerules`.** Системный промпт = обёртка:
Ниже — твой ЗАКОН (.clinerules). Ты ОБЯЗАН следовать ему.
=== НАЧАЛО .clinerules ===
<полный текст .clinerules>
=== КОНЕЦ .clinerules ===

`user` = текст пробы. Никаких подсказок сверху.
Если модель не следует правилам — это результат теста, не повод править скрипт.

## 8. СВОДКА v7 (12.10.2026, `.clinerules` v6.24)

**Сетап:** песочница `sandbox\`, 6 задач, 5 моделей, протокол `[CALL: ...]`.
**Результат: 2 OK / 30.** Только две задачи с `OK` — обе про отказ от `python -c`
(это не использование протокола, а совпадение с правилом).

**Разбивка по вердиктам:**
- `OK`: 2
- `WRONG_ANSWER`: 9 (модель отвечает без вызова)
- `NO_MARKER`: 7 (текст без `[CALL:]`)
- `FAIL`: 7 (illegal путь / инструмент)
- `SOLVED_ILLEGAL`: 2 (решила, но с нарушением)
- `NO_ANSWER`: 3 (не завершила за 5 ходов)

**Вывод:** текстовый протокол `[CALL: read_file ...]` через Ollama /api/chat
**не работает**. Модели:
- пишут `shell ...` без маркера (gemma, gpt-oss);
- отвечают «файл создан» без вызова (gpt-oss, laguna);
- выдают числа без чтения (laguna «49», nemotron «1002»);
- галлюцинируют «3 файла содержат MARKER» (laguna).

**Что делать (v8):**
1. Перейти на XML-теги: `<read_file path="..."/>`, `<shell cmd="..."/>`. Модели
   привыкли к такому формату через Cline.
2. Или включить нативный function calling (Ollama tool support с моделями
   qwen2.5, llama3.1+).
3. Или признать: чистый Ollama-API без нативных tools НЕ ГОДЕН для агентных тестов.
   Тестировать только чат-поведение (v4/v5/v6), а агентность — в живом Cline.
