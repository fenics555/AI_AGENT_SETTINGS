# ЕДИНЫЙ СТЕНД + ЗАКОН SEED (13.10.2026)

## 1. Закон в одну строку
Правила дома: **закон `D:\AI\.clinerules` САМИ НЕ ПРАВИМ — только с разрешения владельца**.
Метод: **один** стенд `AGENT_SETTINGS\checks` (агентный канал `agentic\`), правки сначала в КОПИЯХ
`AGENT_SETTINGS\laws\law_<ключ>.md`, **seed=42 фиксирован**, по 1 прогону на вариант;
итог — отчётом `report.ps1` («что и куда менять») + РЕКОМЕНДАЦИИ владельцу.

## 2. Живые факты (проверено 13.10.2026)
- Два прогона `probe_3` при `-Seed 42` дали **побайтно одинаковый** результат → прежний разброс ±2/3
  был из-за **ОТСУТСТВИЯ seed**, а не из-за правил. `probe_tools.ps1` теперь ставит seed=42 по умолчанию.
- Закон дома (`checks\README`): «расхождение цифр между прогонами = изменение правил, а не шум».
- `probe_3` (seed=42): живой закон **A = 7/15**, кандидат **D = 11/15**, **D+индекс = 12/15**, **vE = 9/15**.
- temperature меняет ТЕКСТ ответа, но не КЛАСС/выбор инструмента (`SKILL_seed_vs_temperature`).

## 5. Возобновление после сбоя (свет/перезагрузка) — 14.10.2026
Сбой (пропало питание) убивает прогон молча: `Start-Process ... -PassThru` -> PID мёртв, часть логов записана, часть — нет.
Порядок восстановления:
1. **Проверить VRAM/GPU перед новым запуском** (обязательно, см. `OLAMA\SKILL_ollama_vram_orphan_runners.md`):
   `nvidia-smi --query-gpu=memory.used,memory.total --format=csv,noheader` (ждать ~0) и `ollama ps` (пусто/100% GPU).
   Сбой мог оставить **orphan `llama-server.exe`** — тогда Ollama уйдёт на CPU (9 t/s вместо ~90). Убить сирот.
2. **Собрать всё, что успело записаться:** «все логи за дату» + `RESULT|` строки. По разрыву времени в именах
   (`probe3_HHMMSS`) видно, где оборвалось. Результаты в логах **усечённые** — не пугаться, читать целевые узлы.
3. **Проверить ветки:** `Get-ChildItem -Force .clinerules_v*` — файлы правок **переживают** перезагрузку (это файлы дома).
4. **Перезапустить только незавершённую часть**, а не весь цикл: сохранять прогресс по узлам (какая ветка/модель уже дала `RESULT`).
5. **Записывать наблюдения сразу в скиллы** (эта запись), а не держать в контексте сессии — контекст гибнет вместе с прогоном.

## 7. ИНДЕКС СКИЛЛОВ — инструмент поиска по смыслу (переехал 15.10.2026)

**`D:\AI\tools\agent\skills_index\`** (рабочее место дома; прежний `repo\INDEX` удалён — в `repo`
не должно быть исполняющих файлов). Зачем: скиллы дома — ГИГАНТЫ
(`SKILL_CHARGE.md` 63 КБ, `AUDIT\SKILL_audit_program.md` 60 КБ, `SKILL_index.md` 26 КБ). Читать целиком нельзя
(переполняет `num_ctx` -> Ollama 400/500). **Индекс НАРЕЗАЕТ скиллы на чанки**, и нужный КУСОК ищется по смыслу.

| Файл | Что делает |
|---|---|
| `skills_index.py build` | сборка базы (ИНКРЕМЕНТ: только изменённые файлы; staging -> publish) |
| `skills_index.py search --full --top 5 "<задача>"` | поиск по смыслу (флаги ДО текста запроса!) |
| `skills_index.py status` | версия, чанков, файлов, размер, возраст |
| `gui.py` / `skills_index_gui.bat` | окно (поиск + перестройка) |
| визард витрины | кнопка 🔍 ПОИСК в топбаре агента |

ФАКТЫ (15.10.2026): **1445 файлов, 12 970 чанков, 51.0 МБ**; база `db\skills_index.db`.
ПРАВИЛА: префиксы `search_document: ` (сборка) / `search_query: ` (поиск) ОБЯЗАТЕЛЬНЫ; модель
`nomic-embed-text-v2-moe:latest`; база ПРОИЗВОДНАЯ (в гит не хранится); корни переносимы
(по умолчанию — от расположения инструмента, перекрываются `settings\settings.json`).
Запуск: `cd D:\AI\tools\agent\skills_index; python -X utf8 skills_index.py search --full --top 5 "<задача>"`.
