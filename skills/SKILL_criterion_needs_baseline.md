# ЛЮБОЙ КРИТЕРИЙ ОПТИМИЗАТОРА СРАВНИВАЕТСЯ С БАЗОЙ, А НЕ С НУЛЁМ

## 1. Симптом

Контрольный замер, вернувший РОВНО базовые цифры, объявлен провалом: «слепые не прошли».
Правка при этом ничего не ухудшила — она вернула вход к базе.

## 2. Замер (02.10.2026 00:01, `results_20261001_235709_ck4.json`)

Итерация R0 (откат `SECTION_MAX`) вернула 15/10/9 — то есть официальную базу 1:1.
Вердикт оптимизатора: `FAIL — причина: laguna: слепые не прошли ['h3_patent_fake']`.

Сверка `log\urn\cline\blind_cmp.py` по трём прогонам:

| прогон | laguna house | h3_patent_fake (слепой) |
|---|---|---|
| база ПРАВКИ 1, 23:04:58 | 9/15 | **FAIL[?]** |
| база повтор, 22:59:44 | 9/15 | PASS |
| R0 приёмка, 23:57:09 | 9/15 | **FAIL[?]** |

Предмет падает **и в базовом прогоне** — это свойство модели на этих правилах, а не регресс.

## 3. Закон

1. **Критерий без базы — не критерий, а тавр.** Требование «слепые = все PASS» при наличии
   в базе хотя бы одного падающего слепого предмета означает: откатывать всегда.
2. **Правильный критерий слепых — дельта:** регресс = «стало хуже, чем в базе».
   В коде: `BASE_BLIND = {("laguna-xs-2.1:latest", "h3_patent_fake"): "FAIL", ...}`.
3. **Это касается всех барьеров, а не только слепых.** Любой новый барьер оптимизатора
   обязан быть проверен вопросом: «какое его значение в БАЗОВОМ прогоне?». Если значения нет
   (никогда не измерено) — барьер сначала измеряется на базе, и только потом применяется.
4. **Вердикт, поставленный на неполной базе, пересчитывается, а не переигрывается.**
   После исправления критерия тот же живой результат дал `ВЕРДИКТ: PASS`.
5. **Ровно базовые цифры = успех приёмки, а не «ничего не изменилось».** Вход вернулся к базе —
   это и было целью итерации.

## 4. Проба

```
cmd /c python -X utf8 D:\AI\log\urn\cline\blind_cmp.py D:\AI\log\urn\cline\blind_cmp_out.txt D:\AI\log\ollama_checks\results_<stamp>_ck4.json
```
Скрипт печатает по трём прогонам слепые предметы и пересчитывает вердикт по текущему коду
`night_optimizer.judge()`. Если вердикт отличается от журнала оптимизатора — ищи новый барьер
без базового значения.
