### 6.1.1. ФОРМАТ ОТЧЁТА В ЧАТ — 4 СТРОКИ, БЕЗ ИСКЛЮЧЕНИЙ (живой факт 16.10.2026)

**Грабля:** нога ведёт прогон и в чат пишет «жив: 2/10» — **ETA пропала**. Владелец спросил:
«вроде в правилах про время конца прогона есть? почему не соблюдаешь?» — **правило есть (§6.1 п.4), нарушение было**.

**ПРАВИЛО: в КАЖДОМ отчёте по прогону (каждые 1–2 шага) — ровно эти 4 строки:**

```
(а) ГОТОВО:   <N>/<всего> — вердикты/цифры каждого закрытого шага
(б) ИДЁТ:     [k/всего] <закон>/<модель>/<тест> (старт HH:mm:ss, идёт X мин)
(в) ETA:      ~HH:mm  (осталось N мин)
(г) ОСТАЛОСЬ: список шагов (закон/модель/тест), ещё не закрытых
```
Плюс одна строка контекста: `сейчас HH:mm:ss · идёт N мин из ~M мин`.

**ГДЕ БРАТЬ ETA (не выдумывать):**
1. Из теста — он сам печатает `ETA: ~HH:mm` и `[ВРЕМЯ] шаг X/Y | прошло N мин | ОСТАЛОСЬ ~M мин`
   (в лог и окно). Если окна нет — эти строки есть в `log\<тест>_<stamp>.log`.
2. Если тест не печатал — считать по факту: `ETA = t0 + среднее_время_шага × оставшиеся_шаги`.
   Среднее — из уже закрытых шагов ЭТОГО прогона (не из головы).

**ЗАПРЕЩЕНО:** отчёт по прогону без строки `ETA`. «Идёт нормально» — не отчёт.

**ЧИТАТЬ ETA-СТРОКИ ИЗ ЛОГА:**
```powershell
$lg = Get-ChildItem '<logDir>' -Filter '*.log' | Sort-Object LastWriteTime -Descending | Select-Object -First 1
Select-String -Path $lg.FullName -Pattern 'ETA|ОЦЕНКА|ВРЕМЯ'
```

### 6.1.2. 🔴 КАНОНИЧЕСКИЙ ЗАПУСК ДРАЙВЕРА — ОКНО НЕ ПУСТОЕ (живые факты 16.10.2026)

**ПОВТОРЯЮЩАЯСЯ ГРАБЛЯ (3 раза за день):** нога запускает прогон, а окно **пустое** → владелец закрывает окно → прогон умирает.

**ПРИЧИНЫ (обе — в драйвере, не в тестах):**

1. ❌ **`$null = & powershell ... 2>&1`** — ГЛУШИТ вывод теста. Окно получает 0 строк → ПУСТОЕ.
   Данные уходят только в файл сводки. Владелец видит пустое окно и закрывает его.
2. ❌ **`Start-Process cmd.exe -ArgumentList @('/c','start','<заголовок>', $inner)`** — `start`
   как аргумент с массивом ломается на кавычках; окно не открывается вовсе (процессов 0).
3. ❌ **кириллица в заголовке окна** → ЧЁРНОЕ окно (см. 6.12.13).

**✅ КАНОН (копировать как есть):**

```powershell
# ШАГ 1. драйвер внутри запускает тест ТАК (вывод ИДЁТ В ЭТО ЖЕ ОКНО):
Start-Process powershell -ArgumentList @('-NoProfile','-ExecutionPolicy','Bypass',
    '-File', (Join-Path $root $j.script)) -NoNewWindow -Wait
#   ВАЖНО: БЕЗ -RedirectStandardOutput и БЕЗ $null = &  -> ход виден в окне.

# ШАГ 2. запуск самого драйвера (видимое окно, ASCII-заголовок НЕ задаём параметром):
$driver = 'D:\AI\AGENT_SETTINGS\tmp\run_<имя>.ps1'
if (-not (Test-Path $driver)) { throw "нет драйвера: $driver" }   # проверка ДО запуска
Start-Process powershell -ArgumentList @('-NoProfile','-ExecutionPolicy','Bypass','-NoExit','-File',$driver) -WindowStyle Normal
```

**ЧЕК-ЛИСТ ПЕРЕД ЗАПУСКОМ ДРАЙВЕРА (все 4 — обязательны):**
1. `Test-Path $driver` → True.
2. В драйвере **нет** `$null = &` и **нет** `-RedirectStandardOutput` (иначе окно пустое).
3. В драйвере **нет** кириллицы в заголовках/аргументах окна.
4. `ParseFile` → 0 ошибок + BOM `EF BB BF`.
5. Сказать владельцу: **«окно `<имя>` — не закрывать, конец = ALL DONE»**.

**САМОПРОВЕРКА ПОСЛЕ СТАРТА (через 10–15 с):**
```powershell
# процессов должно быть >= 2 (драйвер + тест) И сводка должна расти
@(Get-CimInstance Win32_Process -Filter "Name='powershell.exe'" |
   Where-Object { $_.CommandLine -match 'run_|check_' }).Count
```
Если сводка есть, но `RESULT` не появился за 3 мин — смотреть, **пустой ли файл лога теста**.

   когда модели не все.

### 6.8. 🔴 ГРАБЛЯ: REASONING-МОДЕЛИ «ЗАВИСАЮТ» ПРИ МАЛОМ `num_predict` (16.10.2026)

```powershell
[int]$NumCtx = $(if ($CFG -and $CFG.Probes) { $CFG.Probes.NumCtx } else { 16384 })
```

**Что где меняется:** окно (`NumCtx`) · лимиты ответа (`NumPredictMain`/`NumPredictAsk`) ·
таймаут (`TimeoutSec`) · эндпоинт (`OllamaUri`) · усечение (`ReadLimit`/`ShellLimit`) ·
ходы (`MaxTurns`) · seed — **всё в `paths.ps1`**.

**⚠️ ОКНО ДОЛЖНО ХВАТАТЬ (живой урок):** в контекст идут закон (12.7 КБ) + промпт + **все результаты
инструментов** + история ходов. 16 384 токена ≈ 48 КБ — при обходе дома (5–10 файлов) **может не хватить**;
при нехватке Ollama **молча сдвигает окно и выбрасывает НАЧАЛО** (`SKILL_ctx_limit_vs_section_limit`).
**Сейчас `NumCtx = 32768`** — безопасный минимум для агентных задач с обходом.

### 6.12. 🔴🔴 КАТАЛОГ ДЕФЕКТОВ ИЗМЕРИТЕЛЯ (владелец, 16.10.2026) — ДОРОГИЕ ОШИБКИ, ЧИТАТЬ ПЕРЕД РАБОТОЙ

#### 6.12.1. ПЕРЕМЕННАЯ ИСПОЛЬЗУЕТСЯ, НО НЕ ОПРЕДЕЛЕНА (самый дорогой)
**Симптом:** в логе `ОТВЕТ МОДЕЛИ: (пусто)`, хотя модель ответила; флаги-детекторы не срабатывают.
**Факт (16.10.2026):** в `check_3_skills_avail.ps1` переменная **`$ans` НИГДЕ не задавалась**, но
использовалась в 3 местах (`$fakeCall`, `$ritualOk`, вывод ответа). Итог: **все отчёты — «(пусто)»**,
`FAKE_CALL` не ловился, метка `[START:` не виделась. Модели отвечали ВЕРНО, тест показывал пустоту.
**Проверка (ОБЯЗАТЕЛЬНАЯ после правки любого теста):**
```powershell
# каждая использованная переменная ДОЛЖНА иметь определение
Get-ChildItem checks\agentic\check_*.ps1 | ForEach-Object {
  $u=@(Select-String -Path $_.FullName -Pattern '\$ans[^a-zA-Z]').Count
  $d=@(Select-String -Path $_.FullName -Pattern '\$ans\s*=').Count
  if ($u -gt 0 -and $d -eq 0) { Write-Output ($_.Name + ' : $ans БЕЗ ОПРЕДЕЛЕНИЯ') }
}
```
**Лечение:** `$ans = [string]$r.Answer` (или другое верное поле) **до** использования.
**Правило:** PowerShell **НЕ ругается** на неопределённую переменную (даёт `$null`) → дефект **беззвучный**.

#### 6.12.2. ОТВЕТ В `thinking`, А ТЕСТ ЧИТАЕТ `content`

**Лечение:** в `probe_tools.ps1` уже есть: брать `thinking`, если `content` пуст; брать последнее

#### 6.12.11. РЕЗУЛЬТАТ ПИШЕТСЯ В ФАЙЛ, А НЕ В STDOUT (грабля драйвера, 16.10.2026)
**Симптом:** драйвер рапортует `НЕТ RESULT` по всем прогонам, хотя тесты **отработали верно**.
**Причина:** тесты пишут строки `RESULT|…` через `Out-File $resultFile`, то есть **в файл лога**
(`log\check1law_<stamp>.txt`, `log\probe3_<stamp>.txt`), а НЕ в stdout. Драйвер, грепающий
вывод окна (`$out | Where-Object { $_ -match 'RESULT\|' }`), не находит ничего.
**Живой факт:** прогон `run_lawV_2x2` 16.10.2026 — 8/8 «НЕТ RESULT» в сводке, при этом
в `log\check1law_2026-10-16_123034.txt` строка `RESULT|check1law|…|LAW_CITED` лежала на месте.
**Правило:** результат прогона читать ИЗ ФАЙЛА ЛОГА теста, а не из stdout:
```powershell
# найти свежий лог теста и взять из него RESULT
Get-ChildItem '<logDir>' -Filter 'check1law_*.txt' | Sort-Object LastWriteTime -Descending |
    Select-Object -First 1 | ForEach-Object { Select-String -Path $_.FullName -Pattern 'RESULT\||ЭТАЛОН' }
```
**Сверка:** у каждого теста свой префикс файла (`check1law_`, `check2read_`, `probe3_`, `probe4_`,
`check5creo_`, `check6learn_`, `check7prio_`, `check8vol_`) — см. 6.12.5.

#### 6.12.12. ЭТАЛОН MUST MATCH: маска теста ≠ маска замера (16.10.2026)
**Симптом:** мнимые `COUNT_WRONG` и подозрения «код сломался», хотя модель и тест верны.
**Причина:** эталон снят **другой маской**, чем считает тест. Тест 3 (стр. 144–146) считает
`-Filter 'SKILL_*.md'` → `creo=65`; я снял `-Filter '*.md'` → `creo=83`. Разница 18 файлов,
оба числа «правильные», вопросы разные.
**Правило:** перед сверкой выписать маску ИЗ КОДА теста, эталон снимать ТОЙ ЖЕ командой.
Полный разбор — `repo\Prog\SKILL_count_files_template.md` §6.
**ПРОВЕРКА ПЕРЕД ПРОГОНОМ (добавить в чек-лист §6.13):** эталон снят командой, скопированной
из теста (не «похожей»); рядом с числом указана маска.

#### 6.12.13. КИРИЛЛИЦА В АРГУМЕНТЕ `cmd /c start` → ЧЁРНОЕ ОКНО (16.10.2026)
**Симптом:** окно прогона открывается **чёрным** (не отрисовывается), хотя процессы живы и тест работает.
**Причина:** в аргумент `start` передан **русский заголовок окна**:
```powershell
Start-Process cmd.exe -ArgumentList @('/c','start','"СТЕНД: lawG+lawD 2x2"', $inner)   # ❌ ЧЁРНОЕ ОКНО
```
PS 5.1 + `start` + кириллица в аргументе → консоль не получает корректный буфер.
Та же грабля, что `SKILL_ps51_gotchas.md` §1, но там — про **файлы**, а здесь — про **аргумент команды**.
**ЛЕЧЕНИЕ:** заголовок окна — **ASCII-only**:
```powershell
Start-Process cmd.exe -ArgumentList @('/c','start','STEND lawGD 2x2', $inner)   # ✅ ASCII
```
**ВАЖНО:** чёрное окно ≠ мёртвый прогон. Проверка живости — по ФАКТУ (§6.11), не по виду окна:
`Get-Process llama-server` + `ollama ps` + рост файла лога.

#### 6.12.14. ДЛИННЫЙ `Start-Sleep` В ОПРОСЕ → ИНСТРУМЕНТ ПАДАЕТ (16.10.2026)
**Симптом:** `Command timed out after 30000ms`, затем `Command was aborted` — при живом прогоне.
**Причина:** `Start-Sleep -Seconds 25..29` внутри вызова близко к лимиту инструмента (30 с) и упирается в него.
**ПРАВИЛО:** НЕ ставить сон длиннее 20 с в один вызов. Ждать — **повторными короткими опросами**
через отдельные ходы, а не одним длинным сном. Детач запущен = ОДИН короткий опрос (§5.1 п.3).

#### 6.12.15. СВОДКА ДРАЙВЕРА В ОКНЕ ЗАМИРАЕТ, ДАННЫЕ ЖИВУТ В ЛОГЕ (16.10.2026)
**Симптом:** summary-файл не растёт → вывод «прогон встал», хотя он идёт.
**Причина:** summary пишется **после** каждого шага в окне; при чёрном/свёрнутом окне её обновление невидимо.
**ПРАВИЛО:** статус прогона определять ТОЛЬКО по логам тестов (`log\*.txt` растёт) + `ollama ps`.
Итоги собирать из логов (§6.12.11), а не из окна или summary.

#### 6.12.16. БЭКАП В ОДНОЙ ПАЧКЕ С ПЕРЕЗАПИСЬЮ = ПУСТОЙ ФАЙЛ (0 б) — ДОРОГАЯ ГРАБЛЯ (16.10.2026)
**Симптом:** после замены файла «бэкап» существует, но весит **0 байт**, SHA = `E3B0C442…`
(это SHA пустой строки). Данные потеряны, если нет другого источника.

**Живой факт (16.10.2026, замена живого закона на law_D):** в ОДНОЙ пачке выполнил
`Copy-Item .clinerules -> backup.md` и **сразу** `Copy-Item law_D.md -> .clinerules`.
Размер бэкапа = **0**. Спасло только то, что vG2-копия лежала отдельно
(`.clinerules_backup_16.10.2026_vG2_after-fix.md`, SHA совпал 1:1).

**ПРАВИЛО (жёсткое, порядок действий):**
```
ПАЧКА 1: только бэкап  Copy-Item <файл> <бэкап>   -> ПРОВЕРИТЬ размер И SHA
ПАЧКА 2: только замена (после успешной проверки шага 1)
```
**НИКОГДА** не ставить копию-источника и перезапись цели в одну пачку команд.

**ПРОВЕРКА БЭКАПА (обязательная):**
```powershell
$bk='<бэкап>'
'size=' + (Get-Item $bk).Length                              # 0 = ПРОВАЛ
'sha =' + (Get-FileHash $bk -Algorithm SHA256).Hash
$sha -eq 'E3B0C44298FC1C149AFBF4C8996FB92427AE41E4649B934CA495991B7852B855'  # True = ПУСТОЙ
```
**Восстановление:** найти второй источник с тем же содержимым, сверить SHA, перезаписать бэкап.

#### 6.12.17. МОДЕЛЬ БОЛЬШЕ VRAM = 22% НА CPU + ЗАВИСАНИЯ + HTTP 500 (17.10.2026)

**ЖИВЫЕ ЗАМЕРЫ (машина дома: VRAM 16 311 MiB = 15,9 ГБ):**

| модель | размер | влезает в 15,9 ГБ? | PROCESSOR в `ollama ps` |
|---|---|---|---|
| gpt-oss:20b | 13 ГБ | ✅ да | 100% GPU |
| nemotron3-nano | **17–18 ГБ** | ❌ **НЕТ** (+2 ГБ на CPU) | **22% CPU / 78% GPU** |
| laguna-xs-2.1 | 20 ГБ | ❌ **НЕТ** | 36% CPU / 64% GPU |
| gemma4:26b | 18 ГБ | ❌ **НЕТ** | 25% CPU / 75% GPU |
| qwen3.6-35b | 18 ГБ | ❌ **НЕТ** | ~22% CPU / 78% GPU |

**ЧТО ЭТО ЗНАЧИТ:**
1. **Скорость падает в 3–10 раз** — часть слоёв на CPU (видно `22%/78% CPU/GPU`).
2. **`nemotron3` на задачу живой: 434 с (7,2 мин)** и **14 562 токена** — против gemma4 (708 токенов).
3. **РИСК ЗАВИСАНИЯ:** повторный запрос к модели, которая **уже в памяти**, при **переполнении VRAM**
   → Ollama **зависает** (GPU 0–15%, лог теста мертво стоит, `RESULT` не пишется).
   *Живой факт 17.10.2026: прогон встал на 12+ мин на ПЕРВОМ запросе теста 4 (лог 219 б, trace нет).*
4. **HTTP 500 (`ERROR`)** — при переполнении контекста/VRAM: `gpt-oss` тест 4 → `ERROR` в 4 из 5 прогонов.

**ЧЕМ ЭТО НЕ ЛЕЧИТСЯ:**
- ❌ **законом/правилами** — это свойство модели vs железа, а не поведения;
- ❌ **уменьшением `num_ctx`** — проверено замером: при 65536 и 32768 T12a/T12b **одинаковы** (97/77 с);
- ❌ **увеличением `num_ctx`** — только хуже (65536 → модель +1 ГБ → зависание).

**ЧТО ДЕЛАТЬ (правило стенда):**
1. **Перед прогоном** — проверять `ollama ps` + `nvidia-smi`: свободна ли VRAM.
2. **Перед сменой модели** — ГАРАНТИРОВАННАЯ выгрузка, а не только `Stop-Process`:
   ```powershell
   ollama stop <модель> 2>$null | Out-Null      # штатная выгрузка
   Get-Process llama-server -EA SilentlyContinue | Stop-Process -Force
   Start-Sleep -Seconds 5                        # дать Ollama освободить VRAM
   # проверить: nvidia-smi -> ~0 MiB, ollama ps -> пусто
   ```
3. **В отчёте указывать** `PROCESSOR` из `ollama ps`: `22%/78% CPU/GPU` = модель НЕ влезла — это
   объяснение медленности и возможных зависаний.
4. **`ERROR` в RESULT ≠ поведение модели** — это сбой раннера. Различать в выводах!
5. **Планируя прогон по времени:** модели >16 ГБ брать **последними** и **по одной**, с проверкой
   живости (§6.11); при 12+ мин без записи в лог — модель зависла, не ждать.

**ВЫВОД ДЛЯ ДОМА:** `laguna` (20 ГБ) и `gemma4` (18 ГБ) — тоже частично на CPU. Если нужна
**полная скорость** — брать модели **≤13 ГБ** (gpt-oss) или кванты поменьше.

### 8.1. Пять стандартных пунктов (спрашиваются ВСЕГДА, после любого задания)
1. **«Что ты делала?»** — пересказ шагов + какие инструменты звала.

   Стенд подаёт РЕАЛЬНЫЕ вызовы из trace, модель называет ОДНУ причину.
4. **Ш4 — «Что изменить или дополнить в правилах/скиллах, чтобы выполнить ЭТО задание? Одну строку, конкретно. Это опрос — менять ничего не надо.»** — опрос поведения, НЕ команда.

> 🔴 **ЕДИНАЯ ФОРМУЛИРОВКА — ОБЯЗАТЕЛЬНА (владелец, 15.10.2026), во ВСЕХ 6 тестах ОДИН текст.**

>
> **Ключевые слова, которые нельзя терять:**
> - **«ИМЕННО ЭТО задание»** — привязка к контексту. Без неё модель читает как постановку

>   Пример дефекта: laguna на Ш4 ответила «Прочитаю MANIFEST.md…» — это план действия, не ответ.
> - **«Одну строку / одну причину»** — запрет плана действий и воды.
> - **«Конкретно»** — запрет общих слов.
> - **«Это опрос — менять ничего не надо»** (Ш4) — снимает у модели желание что-то чинить сейчас.

> про преграду, а не про её самооценку.

### 8.3. Откуда берутся флаги (механика сверки)

## 12. ГРАБЛИ WINDOWS (записаны 15.10.2026)

### 12.1. КОДИРОВКИ: Select-String «не видит» строку (UTF-8 vs ANSI)
**Симптом:** слово в файле **визуально есть**, но `Select-String -Pattern 'СЛОВО'` его **не находит**.
**Причина:** файл в ANSI/Windows-1251, а PowerShell ищет в другой кодировке (или наоборот).
**Лечение:** указывать кодировку явно — `Select-String -Encoding utf8` или `Get-Content -Encoding utf8`.
**Источник:** живое наблюдение gemma4 (Ш4, тест 2, 15.10.2026): «на Win32NT это частая причина
«невидимых» для `Select-String` строк (когда слово визуально есть, но поиск его не видит)».
**Связь:** §13 (байты ≠ символы) — та же природа: кириллица в UTF-8 = 2 байта.

### 12.3. ГРАБЛЯ: ПРАВКА .ps1 БЕЗ BOM ЛОМАЕТ СКРИПТ (записано 15.10.2026)

**Симптом:** после массовой замены через `Get-Content -Raw` + `[IO.File]::WriteAllText($f,$c,(New-Object Text.UTF8Encoding($false)))`
все 6 тестов перестали парситься: `Непредвиденная лексема "<кириллица>" в выражении или операторе`.

**Причина:** `UTF8Encoding($false)` пишет **БЕЗ BOM**. PowerShell 5.1 без BOM читает файл как ANSI →
кириллица превращается в мусор → парсер валится на русских строках. **Текст НЕ повреждён** (в UTF-8 он цел) — теряется только признак кодировки.

**Проверка (первые 3 байта должны быть `EF BB BF`):**
```powershell
$b=[IO.File]::ReadAllBytes($p); ($b[0] -eq 0xEF -and $b[1] -eq 0xBB -and $b[2] -eq 0xBF)
```

**Лечение (возврат BOM, текст сохраняется):**
```powershell
$txt=[IO.File]::ReadAllText($p,[Text.Encoding]::UTF8)
[IO.File]::WriteAllText($p,$txt,(New-Object Text.UTF8Encoding($true)))   # $true = С BOM
```

**ПРАВИЛО:** русские `.ps1` править ТОЛЬКО `editor`-инструментом (BOM сохраняется). Массовые замены
через PowerShell — только с `UTF8Encoding($true)` + проверка `[Parser]::ParseFile` по ВСЕМ затронутым файлам.

### 12.4. «ТРОНУЛ ФАЙЛ» = read_file ИЛИ путь в shell (грабля v14.1)
Модель вправе читать файл через `shell` (`Select-String`, `Get-Content`) — это **НЕ** провал.
Судить «читал/не читал» только по `read_file` → **ложный провал** (проверено 15.10.2026:
gemma4 читала `read_real.txt` через `Select-String`, а стенд дал `GUESSED` + флаг `ВЫДУМАЛ_СЕБЯ`).
**Правило:** «тронутое» = пути из `read_file` + пути, упомянутые в `shell`-командах.
Расширения в regex: `.md|.txt` (не только `.md`).

## 13. БАЙТЫ ≠ СИМВОЛЫ (важный факт, 15.10.2026) — НЕ ЗАБЫВАТЬ

**Кириллица в UTF-8: 1 русская буква = 2 байта, но 1 СИМВОЛ.**

Живой факт измерителя:
```
D:\AI\.clinerules  ->  bytes: 12411   (на диске)
                       ReadAllText: 7944     (символов!)
                       Get-Content -Raw utf8: 7944  (так же)
Разница 4467 «лишних» байта — это русские буквы (по 2 байта каждая).
```

### 13.1. Почему это ломает замеры
1. **Сравнение размеров врёт.** `(Get-Item).Length` = **БАЙТЫ** (12 411).
   `$t.Length` в PowerShell = **СИМВОЛЫ** (7 944). Это РАЗНЫЕ числа одного файла.
2. **Усечение по символам ≠ по байтам.** `Substring(0, 6000)` берёт 6 000 **символов**,
   а байт при этом ~9 400. Считать «влезло ли» надо в ОДНОЙ мере.
3. **Оценка токенов:** кириллица дороже латиницы (~1,5–2 токена на слово).
   `num_ctx` считается в токенах, не в байтах.
4. **§3.0 теста 1:** правило обряда требовало «прочитать файл» — при этом правила УЖЕ
   подставлены в промпт (7 944 симв. = весь закон). Дубль чтения → усечение → потеря конца.

### 13.2. ПРАВИЛО ЗАМЕРА
- Размер файла на диске — **только** через `.Length` файла (байты) И отдельно символов.
- При усечении/лимитах — указывать, **чего** мера: символы или байты.
- В отчётах писать обе цифры, если важно: `12 411 б / 7 944 симв.`

### 13.3. ВЫВОД ПО ТЕСТУ 1 (15.10.2026)
Правила в промпт **доходят целиком** (7 944 симв.). Но §3.0 велит **прочитать файл** —
а чтение усекается до 6 000 симв. → **раздел в конце закона (§5.4 КРАШ/REVIVE) теряется**.
Отсюда `LAW_READ` (читала, раздела нет) и флаг `ДОГАДКА`.

### 16.5. ОБНОВЛЁННЫЙ АЛГОРИТМ (порядок работы с флагом)
```
Флаг поставлен
    ↓
1. Прочитать ДОСЛОВНЫЙ ответ + trace (не таблицу вердиктов)
    ↓
2. Прогнать тест НА СЕБЕ руками, получить эталон
    ↓
3. Проверить критерий на известном ответе (подставить верный текст)
   ├─ FAIL на верном ответе → ДЕФЕКТ ТЕСТА (не модель, не правило)
   └─ PASS → идём дальше
    ↓
4. Спросить модель (Ш3): «почему так повела себя, что менять в задании/законе»
   → её ответ = ГОТОВАЯ ГИПОТЕЗА правки (правило §4: источник лучшей правки — сама модель)
    ↓
5. Точечная правка ОДНОЙ формулировкой в КОПИЮ закона (laws\law_<ключ>.md)
   — не бояться править под одну модель
    ↓
6. ОДИН замер. Четыре исхода:
   ├─ все прошли (включая флагованную) → ПРИНЯТЬ, правило работает
   ├─ флагованная прошла, другая упала → ОТКАТ (перестановка провала)
   ├─ флагованная падает, другие целы → другая формулировка; нет идеи → флаг, тема закрыта
   └─ все упали → ОТКАТ (класс «добавление текста = шум»)
```

### 17.1. 🔴 ЗАПУСК ДОЛГИХ ПРОГОНОВ: НЕ ЧЕРЕЗ РОДИТЕЛЯ (живой провал 17.10.2026)

**ГРАБЛЯ (проверено на себе, 3 провала подряд):**
```powershell
Start-Process powershell -ArgumentList @('-NoExit','-File','run.ps1')   # ❌ УМИРАЕТ
```
**Почему:** процесс-родитель (shell агента) живёт **~30 с** (таймаут инструмента). Когда он
умирает — **дочернее окно убивается вместе с ним**. Файл сводки создаётся (`START` записан),
первый шаг теста успевает начаться (лог обновляется), затем **всё обрывается**.
**Признак:** сводка есть, а `процессов: 0`; окна нет; лог теста оборван на середине.

**ЛЕЧЕНИЕ (работает):**
```powershell
Start-Process cmd -ArgumentList @('/c', 'python -X utf8 script.py > out.txt 2>&1') `
  -WorkingDirectory 'D:\AI\AGENT_SETTINGS\tmp' -WindowStyle Minimized -PassThru
```
`cmd /c` **отвязывает** процесс от родителя: родитель умирает -> **работа продолжается**.
Проверено: `cmd` PID исчез, `python` PID остался -> замер пишет в файл.

**ОБЯЗАТЕЛЬНО:**
1. **Вывод в ФАЙЛ** (`> out.txt 2>&1`), не только в окно — иначе прогресс не виден;
2. Python: **`print(..., flush=True)`** после каждого шага, иначе буфер не сбросится
   до конца (файл будет 0 б, хотя работа идёт);
3. Для драйвера стенда: внутри него `Start-Process ... -Wait` уже **нормально**
   (родитель = сам драйвер, он живёт долго), но **сам драйвер** запускать через `cmd /c ...`.

**ПРАВИЛО:** долгий прогон (> 30 с) через инструмент агента — **только отвязанным** способом.
Прямой `Start-Process` из инструмента = прогон умрёт на 30-й секунде.

### 16.7. Чего НЕ делать
1. **Не начинать с допроса модели (Ш1).** Сначала дословный ответ и trace.
2. **Не ставить крест на флагованной модели.** Флаг — диагноз для точечной правки, а не приговор (v26→v30).
3. **Не менять правило вслепую, если провал групповой** — сначала дословный ответ и trace, потом ОДНА правка.
4. **Не считать «правило есть на диске» = «дошло до модели»** (`SKILL_section_cut_silently`).
5. **Не считать «вердикт FAIL» = «модель виновата»** — два раза за день FAIL был дефектом чекера.
6. **Не отказываться от правки без одного из трёх оснований** (перестановка / деградация соседей / пять попыток).
