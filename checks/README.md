# checks — программы проверки локальных моделей (Ollama)

Автономные проверки дома: измеряют **скорость** модели и её **склонность выдумывать**.
Ничего не меняют в моделях — только опрашивают сервер Ollama через `/api/chat`.

## Что здесь

| Файл | Что делает |
|---|---|
| `strict_test.py` | 10 вопросов: 6 проверяемых фактов + 4 ловушки (несуществующие сущности). Даёт факты/ловушки и t/s по каждой модели. |
| `verify_prompt_test.py` | A/B: тот же вопрос **без** правила и **с** системным правилом, взятым из мастер-файла `D:\AI\.clinerules` (раздел АНТИ-ГАЛЛЮЦИНАЦИИ). 3 ловушки + контроль (реальный ГОСТ 2.106-96). |
| `loop_revive_test.py` | 3 семейства × 10 предметов × {plain, house}: выдумки (H), петля (L), REVIVE (R). `house` берёт правила из мастер-файла, поэтому стенд не мерит устаревший текст. |
| `speed_check.py` | Замер скорости на заданном окне контекста (по умолчанию 202752): load, prompt t/s, gen t/s. Доказывает, что смена параметров сэмплинга скорость не меняет. |
| `RUN_strict_test.bat` | запуск `strict_test.py` |
| `RUN_verify_test.bat` | запуск `verify_prompt_test.py` (think=ON, 1500 токенов) |
| `RUN_speed_check.bat` | запуск `speed_check.py` |
| `RUN_all_checks.bat` | полный прогон всех локальных моделей (кроме embedding), ~10 мин |
| `RUN_models_v3.bat` | замер честности на 5 моделях (эксперимент v3), think=OFF |
| `RUN_battery_v3.bat` | полная батарея: A strict → B loop/revive (13 предметов) → C experiment v3, на 5 моделях |
| `tests/checkers_regression.py` | регрессия чекеров на РЕАЛЬНЫХ ответах; запускать ДО и ПОСЛЕ каждой правки чекера |
| `tests/rescore_run.py` | пересчёт готового прогона текущими чекерами (старый вердикт результатом не является) |
| `LOG_tuning.md` | журнал замысла «модель сама пишет свои локальные правила и тестирует себя петлёй» (без кода, слово владельца 01.10.2026) |

Вывод прогонов идёт в дом-лог: `D:\AI\log\ollama_checks\` (см. `retention.json`, ключ `ollama_checks` = 56 дней).

## Как запускать

```bat
cd /d D:\AI\AGENT_SETTINGS\checks
RUN_strict_test.bat gemma4:26b gemma4:12b
RUN_verify_test.bat gemma4:26b
RUN_speed_check.bat gemma4:26b
RUN_all_checks.bat
```

Вывод: `D:\AI\log\ollama_checks\` (файлы `report_<дата>.md`, `results_<дата>.json`,
`verify_<дата>.md`, `speed_<дата>.json`, `progress.log`). Сводный отчёт по задаче — в
`D:\AI\log\reports\`. Каталог вывода можно переопределить переменной `CHECKS_OUT`.

Настройки прогона — переменные окружения: `TEST_NUM_CTX`, `TEST_NUM_PREDICT`, `TEST_SEED`,
`TEST_THINK`; для A/B — `VP_NUM_CTX`, `VP_NUM_PREDICT`, `VP_SEED`; для скорости — `SPEED_NUM_CTX`,
`SPEED_NUM_PREDICT`, `SPEED_PROMPT`.

## Как читать результат

- **Ловушка пройдена** = модель ответила «не существует / нет данных», а НЕ описала содержимое.
  Формулировки вида «ГОСТ 12345-67 устанавливает…» = выдумка, даже если звучит гладко.
- Контрольный вопрос (реальный ГОСТ 2.106-96) показывает обратную ошибку: если модель
  отвечает «НЕТ ДАННЫХ» на существующий документ — правило слишком жёсткое для этой модели.
- `t/s` в отчёте — только генерация (`eval_count / eval_duration`), без загрузки модели.

## Важно при запуске

`OLLAMA_MAX_LOADED_MODELS=1`: каждая проверка загружает модель, поэтому она **вытеснит**
модель, с которой вы сейчас работаете (в Cline/приложении Ollama). Запускать, когда работа
не идёт, либо предупреждать владельца.
