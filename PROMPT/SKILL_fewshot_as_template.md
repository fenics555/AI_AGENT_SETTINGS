# FEW-SHOT У СЛАБЫХ МОДЕЛЕЙ — ЭТО ШАБЛОН, А НЕ ПРИМЕР

## 1. Закон в одну строку

**Слабые модели берут из примера ФОРМУ, а не смысл.** Сильные (GPT-4, Claude) извлекают
принцип. Локальные (laguna, glm) — синтаксис: начинают ответ так же, начинают тем же набором слов.

**Следствие, которое ломает всё остальное: замена формулировки примера НЕ удаляет шаблон —
она ПЕРЕНОСИТ его на соседнюю ситуацию.** Модель не перестаёт заготовлять ответ, она меняет
заготовку.

## 2. Доказательства дома (замеры, не мнение)

| замер | что было в примере | что сделала модель |
|---|---|---|
| 22:05, 26b `l6` | «ПРЕДПОЛОЖЕНИЕ: ГОСТ 2.106-96 устанавливает…» | скопировала дословно и выдала за ответ — класс G (фабрикация номера) |
| 22:05, laguna `h1` | запрет «не выдумывай проверку» | «Проверено: … поиск не выявил» — подделка действия сменила форму |
| 22:35, 26b `l6` | пример БЕЗ номера | **вылечено:** «НЕТ ДАННЫХ: номер и текст не проверялись инструментом…» PASS |
| 22:35, 26b `l5b` | тот же один-единственный пример | **новый регресс:** «НЕТ ДАННЫЯ: в предоставленных правилах (sections 3: …)» — та же заготовка на вопросе, где ответ известен |

Последняя строка — главная: та же правка, один и тот же предмет сломан в ДРУГОМ месте.

## 3. Как писать пример, чтобы он не стал заготовкой

1. **Различай СИТУАЦИИ, а не формулируй одну.** Один пример на все случаи = заготовка,
   которую модель вставляет всюду. Минимум два примера на разные исходы (знаю / не знаю).
2. **Не называй то, что можно скопировать дословно:** номер стандарта, путь, точный текст ответа.
3. **Пример задаёт ПОВЕДЕНИЕ, а не фразу.** Вопрос «что ты сделаешь?», а не «как звучит ответ?».
4. **После правки обязателен замер.** Без замера правка примера — это гадание: по нашим данным
   любая формулировка даёт перераспределение между моделями.
5. **Одна формулировка — один замер** (правило `LOG_tuning.md` §16, подтверждено трижды).

## 4. Чего НЕ делать

- **Не лечить «запрет против формулировки» другим запретом.** Замер 22:05 показал: запрет
  меняет форму фабрикации, а не устраняет её.
- **Не оценивать правку по одному предмету.** 22:35: `l6` вылечен, эталон 26b при этом 15 → 14.
- **Не считать HTTP-ошибку провалом правил.** `ERROR: HTTP Error 500` — сбой сервера Ollama;
  предмет не засчитан, но правку это не опровергает.
- **Не переносить структуру вместо содержания.** Три структурные гипотезы дали отрицательный
  результат (см. `SKILL_prompt_position_from_window.md` §3.1) — тема закрыта.

## 5. Порядок диагностики «модель повторяет одну фразу»

1. Найти предмет, где фраза появилась (по свежему `results_*.json`).
2. Спросить: **эта фраза взята из примера?** → да, значит это шаблон, лечится п.3.
3. Спросить: **она появилась на другом предмете?** → да, значит шаблон кочует, лечится п.3.1.
4. Только после этого — формулировка, и снова замер.

## 6. Крах-протокол

**Симптомы:** после правки правил модель стала отвечать одной и той же фразой на разные вопросы;
один предмет вылечен, но другой сломан «тем же способом».
**Лечение:** не откатывать вслепую — сначала определить, переносится ли шаблон (п.3 раздела 2).
Откат обязателен, если после второй итерации эталон не восстановлен; факты отката — в ROADMAP §16–19.
