# ПОЛНЫЙ БЛОК ПРАВИЛ = ШУМ ДЛЯ СЛАБОЙ МОДЕЛИ

## 1. Симптом

Правка не содержительно, а чисто техническая: поднят `SECTION_MAX` 7000 → 10000, чтобы хвост
раздела ВОСКРЕШЕНИЕ (9 560 символов) перестал молча резаться. Замер выглядит честно:
health check зелёный, эталон 26b держится. Слабая модель при этом **падает вдвое**.

## 2. Замер (01.10.2026 23:39, `results_20261001_233902_ck4.json`)

Вход: `p20sm.log:2` `chars=21008` (было 18 448), `sha256=97b40137`.

| модель house | база (`chars=18448`) | `SECTION_MAX=10000` (`chars=21008`) |

## 3. Причина (объяснение, не доказанный факт)

Разница между входами — **2 560 символов хвоста ВОСКРЕШЕНИЕ** (КРАШ И ВОСКРЕШЕНИЕ,
строка-доказательство, ПОЛУПРАВКА). Для 26b это полезный текст. Для laguna — объём,
в котором легко узнать ритуал и открыть его там, где требовался ответ: `l3_scenario` получил
класс **Б (ложный REVIVE)**. Метка «ПРЕДПОЛОЖЕНИЕ» об этом, а не «ФАКТ».

## 4. Закон

1. **Обрезка правил и их избыток — два разных дефекта, и лечатся они противоположно.**
   Молчаливую обрезку чинить надо (`SKILL_section_cut_silently.md`); избыток — нельзя.
2. **Health check не измеряет полезность.** `rules ok: 21008 символов` зелёный при провале 9 → 4.
   Зелёное здоровье ≠ здоровая модель.
3. **Эталон 26b не защищает остальных.** 26b 15/15 держался в обоих входах — на него смотреть
   нельзя как на индикатор: изменение промпта проверяется на СЛАБЕЙШЕЙ модели.
4. **Критерий приёмки правки промпта обязан включать слабейшую модель**, а не только эталон.
5. **Откат при этом обязателен и подтверждается живым замером** — не «судя по логике, вернётся».
